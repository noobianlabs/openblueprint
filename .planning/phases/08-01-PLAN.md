# Phase 8 — Visual parity

**Milestone:** v1.2
**Depends on:** Phase 7 (shipped 2026-08-30)
**Driver:** user critique — the closed-source product's renders, part visuals, and CAD
presentation look better than ours. Close the gap without betraying the keyless default.

## Requirements

- **REQ-17** — The MECH scene reads like a product render, not a debug view: bevelled
  bodies, believable materials, soft key/fill/rim lighting, a contact shadow, and a
  ground that recedes instead of a flat grid.
- **REQ-18** — Part illustrations have depth: consistent isometric projection, top-light
  shading, per-shape detailing (silkscreen, chips, pads, threads), and a seated shadow.
- **REQ-19** — Every project gets a hero "product shot" and card cover rendered FROM its
  own 3D massing model (offscreen three.js render → image), replacing the glyph-on-gradient.
  Keyless by construction: the render is derived, not fetched.
- **REQ-20** — The unlayered `.microlabel` specificity trap in globals.css is fixed so
  Tailwind utilities compose with it; no visual regressions.

## Success criteria

1. `npm run build` clean; zero console errors across all six tabs, landing, projects.
2. Side-by-side: MECH and INFO screenshots visibly closer to a product render than
   the Phase 6/7 captures (screenshots kept in docs/screenshots for comparison).
3. STL export, explode, selection, deep links, sourcing links, ZIP export all still work.
4. `.microlabel` composes with Tailwind color/size utilities (grep-verified in built CSS).

## Standing executor constraints (unchanged from Phase 7)

Node 22 PATH + `cd` into the repo before npm/npx; never `npm --prefix`; no executor
starts or stops servers; write early and incrementally; `npm run build` is the gate,
tsc alone is not; no new dependencies; no emoji in UI.

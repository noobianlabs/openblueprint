# Phase 7 — Post-v1 polish

**Milestone:** v1.1
**Depends on:** Phase 6 (shipped 2026-08-30)
**Requirements:** REQ-14, REQ-15, REQ-16 (new, below)

## Why this phase

v1 shipped with three known limits recorded in STATE.md. Two are fixable now;
the third (exercising the Claude engine) stays parked because there is no
`ANTHROPIC_API_KEY` in this environment. This phase closes the fixable two and
adds the export that makes a design portable.

## Requirements

- **REQ-14** — At 0% explode, the MECH assembly reads *assembled*: every child
  sits on or inside its parent per `pkg.assembly`, not scattered around it.
- **REQ-15** — Every part offers a sourcing link that leads somewhere real. Links
  are searches, never fabricated exact-product URLs.
- **REQ-16** — A project exports as a single ZIP: design JSON, BOM CSV,
  instructions Markdown, and the assembly STL. Generated client-side.

## Plans

- 07-01: three disjoint work items, executed in one parallel wave

### Work item A — MECH at-rest nesting (REQ-14)
Owns `src/components/tabs/mech/MechViewer.tsx` and any new file under
`src/components/tabs/mech/`.

Children are placed relative to the parent's body: parts mounted *to* a printed
bracket or plate sit on its top face; parts mounted *inside* an enclosure sit
within its volume, which is why enclosures render transparent. Explode still
pushes everything apart from the centroid — this changes only the rest pose.
Ships with the stale "reads semi-exploded" caveat deleted from README and
STATE.md.

### Work item B — Sourcing links (REQ-15)
Owns `src/lib/design/sourcing.ts` (new) and the part row in
`src/components/tabs/PartsTab.tsx`.

A search URL built from the part name, per vendor. No invented product IDs, no
affiliate parameters, no claim of stock or price. The UI says these are searches.

### Work item C — Project ZIP export (REQ-16)
Owns `src/lib/design/export.ts` (new) and the export control in
`src/components/ProjectView.tsx`.

Zip written by hand (stored/no-compression entries are enough) so no dependency
is added. Reuses `toStl` from `src/lib/design/stl.ts` — does not modify it.

## Success criteria

1. `npm run build` clean; a seed and a generated design both render all six tabs
   with no console errors on the production server.
2. MECH at 0% explode reads as one assembled object; the slider still separates it.
3. Every part row links out to a working search for that part.
4. The exported ZIP opens and contains four non-empty, well-formed members.

## Constraints for executors

- `cd /Users/noobian/dev/openblueprint` and
  `export PATH="$HOME/.nvm/versions/node/v22.19.0/bin:$PATH"` before any npm/npx.
  Node 18.7 is the shell default and fails the Next build.
- **No executor starts or stops a server.** The orchestrator owns servers and all
  browser verification. A `next dev` run during Phase 6 clobbered the production
  `.next`.
- `npx tsc --noEmit` is necessary but not sufficient — its incremental cache
  passed a file `next build` then rejected. `npm run build` is the real gate.
- Write files early and incrementally; a session limit killed two executors
  mid-flight in Phase 6 and only on-disk work survived.
